## Scaffold (2026-09-30)

| #   | Decision                                                                                    | Why                                                                                                                                                    | Rejected alternative                                                                             |

| D1  | **pnpm workspaces monorepo** (`apps/api`, `apps/mobile`, `packages/shared`)                 | One repo to review; shared contract without publishing packages                                                                                        | Nx / Turborepo: caching + generators we don't need for 2 apps                                    |
| D2  | **Shared Zod schemas** in `packages/shared`                                                 | One validation rule used by NestJS DTOs _and_ React Hook Form; types inferred, never hand-written                                                      | class-validator DTOs on the API + separate Zod on mobile → every rule written twice and drifts   |
| D3  | **`node-linker=hoisted`**                                                                   | Metro and several RN native modules still assume a flat `node_modules`                                                                                 | pnpm's default isolated layout: works for Node, fragile for React Native                         |
| D4  | **NestJS 11**, not 12                                                                       | Nest 12 (Aug 2026) is ESM-only and `nestjs-zod` peers `@nestjs/common ^10 \|\| ^11`                                                                    | Latest major: would mean fighting ecosystem lag in a timed exercise                              |
| D5  | **Prisma 7.10** (stable), not 8 RC                                                          | Stable; typed client; committed SQL migrations; driver adapter (`@prisma/adapter-pg`) = no Rust query engine                                           | Drizzle (closer to SQL, also good); TypeORM (weaker types, decorator entities)                   |
| D6  | **UUID v7 primary keys**                                                                    | Unguessable in URLs like v4, but time-ordered → better B-tree index locality                                                                           | Autoincrement ints: leak counts, enumerable                                                      |
| D7  | **snake_case tables/columns via `@map`**                                                    | Idiomatic Postgres; camelCase in TS                                                                                                                    | Prisma defaults (quoted camelCase identifiers in SQL)                                            |
| D8  | **Watcher = row in `pet_watchers`**, ownership = `pets.owner_id`                            | Brief: owner/watcher are per-pet relationships, not global roles                                                                                       | `role` column on `users`                                                                         |
| D9  | **One `invitations` row per (pet, invitee)**, token rotated on re-invite                    | No duplicate pending invites without a partial unique index; clean history per pair                                                                    | Row per send + partial unique index `WHERE status='PENDING'` (Prisma can't express it in schema) |
| D10 | **Care task = recurrence rule** (`timeOfDay` minutes, `DAILY`/`WEEKLY`, `daysOfWeek int[]`) | "Feed 08:00 daily" is 1 row; Today/Weekly computed by a pure, unit-tested function                                                                     | Materialised occurrences: needs a generator job, backfills, cleanup                              |
| D11 | **Wall-clock times in the viewer's local timezone**                                         | Pets eat at "8am where the pet is"; owner and watcher are normally in the same place                                                                   | Store UTC instants: breaks on DST and for recurring rules                                        |
| D12 | **Short JWT access token (15 min) + opaque rotating refresh token, stored hashed**          | Refresh tokens are revocable (logout, password reset, reuse detection)                                                                                 | Long-lived JWT only: can't log anyone out                                                        |
| D13 | **All one-time tokens stored as SHA-256 hashes** (refresh, reset, invite)                   | DB leak ≠ usable links. Tokens are high-entropy random, so a fast hash is enough                                                                       | Plain tokens; or bcrypt/argon2 for tokens (slow hash is only needed for low-entropy passwords)   |
| D14 | **argon2id** for passwords                                                                  | OWASP first recommendation                                                                                                                             | bcrypt (fine, 72-byte limit)                                                                     |
| D15 | **404 (not 403) when a pet isn't visible to the caller**                                    | Don't reveal that a pet ID exists                                                                                                                      | 403 everywhere                                                                                   |
| D16 | **One error envelope** `{statusCode, code, message, fieldErrors?}` via a global filter      | Client maps `fieldErrors` straight to RHF `setError`; stable `code`s for UI copy                                                                       | Nest default shapes (differ between validation and HTTP errors)                                  |
| D17 | **Env validated with Zod at boot**                                                          | Fail fast on misconfiguration                                                                                                                          | Reading `process.env` ad hoc                                                                     |
| D18 | **Docker Compose for infra only** (Postgres, SeaweedFS, Mailpit); API + app run on host     | Hot reload + simulators reach `localhost` without container networking                                                                                 | API in a container: slower loop, extra networking config for devices                             |
| D19 | **SeaweedFS for S3, Mailpit for SMTP** (was MinIO, see D35)                                 | Real presigned URLs and real SMTP locally; production = change env vars (S3/SES)                                                                       | Logging links / writing files: doesn't exercise the real code path                               |
| D20 | **Expo Router**                                                                             | File-based routes = deep links for free (`app/invites/[token].tsx` ↔ `petwatch://invites/<token>`); `Stack.Protected` for auth gating                  | React Navigation + manual linking config                                                         |
| D21 | **Gluestack UI v3 + NativeWind v4 (Tailwind 3)**                                            | Stable pair. Gluestack's v5 CLI labels itself alpha and its generated components failed `tsc` against NativeWind v5 RC (breaks the "fully typed" rule) | Gluestack v5 + NativeWind v5 RC (re-evaluate when stable)                                        |
| D22 | **TypeScript 6.0 everywhere**                                                               | Expo SDK 57 pins TS 6.0; one compiler across the repo                                                                                                  | TS 7 (native Go compiler; tooling like ts-jest not ready)                                        |
| D23 | **Jotai for UI state** (view mode, pet filter); **Context only for the auth session**       | Atoms re-render only subscribers; no provider needed                                                                                                   | Context for everything: re-renders whole subtree on each change                                  |

| D25 | **Development build** (`expo run:ios/android`), not Expo Go                                 | Custom URL scheme `petwatch://` and native modules need our own binary                                                                                 | Expo Go: deep links become `exp://…/--/…`                                                        |

## Auth (2026-09-30)

| #   | Decision                                                                                                                                                                                                                                                                                                                                                      | Why                                                                                                                                                                                                                                                                                                    | Rejected                                                                                                                                                                                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D40 | **Refresh rotation = look up by hash, then claim by id** with `updateMany({ where: { id, revokedAt: null } })` (count must be 1) in one transaction with the new token. Presenting a revoked token = reuse → **revokes all of the user's refresh tokens (all devices)**. Requires the client's single-flight refresh (AUTH-4)                                 | The conditional claim is atomic, so two concurrent refreshes can't both succeed. Without single-flight on the client, two parallel 401s would look like reuse and sign the user out                                                                                                                    | Read-then-update without a condition: under READ COMMITTED both requests see "not revoked". _With more time:_ per-device token families (revoke only the compromised chain)                                                                                                                                                                     |
| D41 | **`ThrottlerGuard` on `AuthController` only** (defaults 10/min per IP, 5/min for login and forgot-password, set by `THROTTLE_*` env), in-memory storage                                                                                                                                                                                                       | Protects the endpoints worth brute-forcing without rate-limiting normal app traffic                                                                                                                                                                                                                    | Global guard (throttles every screen load); Redis storage (needed only with more than one API instance)                                                                                                                                                                                                                                         |
| D42 | **E2E against real services**: API e2e (Jest + supertest) boots the real `AppModule` on a separate `petwatch_test` DB (globalSetup: create if missing + `migrate deploy`; truncated before each test), reads emails back from Mailpit; mobile e2e with Maestro. Throttle limits come from config (named `default`/`strict` throttlers), raised in `.env.test` | Bugs that matter (SQL, CHECK constraints, SMTP, S3 signing, guards wiring) only show up with real services; config-driven limits keep prod code free of test branches                                                                                                                                  | `migrate reset` in globalSetup (Prisma blocks it for AI agents without per-run consent, and a full drop isn't needed when data is truncated anyway); mocked Prisma in e2e; transaction-per-test rollback (the app opens its own transactions and connections); `NODE_ENV === 'test'` to skip throttling; Detox (native test harness in the app) |
| D43 | **Password reset returns a new session** (200 `AuthResponse`, issued after revoking every refresh token); the mobile app signs in and lands on Home                                                                                                                                                                                                           | The design auto-logs in after reset, and the client doesn't know the email at that point; using the emailed single-use token already proves control of the mailbox                                                                                                                                     | 204 + send the user to Login (extra step, contradicts the design); putting the email in the reset link (PII in URLs and mail logs)                                                                                                                                                                                                              |
| D44 | **Photo keys are scoped to the pet and chosen by the server** (`pets/{petId}/{uuid}.jpg`); confirm checks the prefix and that the object exists. Add pet = create, then upload; Edit uploads on pick and Save waits for it. Presigning uses `requestChecksumCalculation: 'WHEN_REQUIRED'`                                                                     | The server can prove a key belongs to the pet without trusting the client; no orphaned uploads from abandoned forms. The SDK's default signs a CRC32 of an empty body into presigned PUTs, so every real upload failed (BadDigest)                                                                     | User-scoped temp uploads before the pet exists (orphans, needs a cleanup job, weaker check); taking the key from the client                                                                                                                                                                                                                     |
| D45 | **Pending deep link from `useLinkingURL()`, not `+native-intent`; LogBox ignores Expo Router's "state update on a component that hasn't mounted yet"**                                                                                                                                                                                                        | Expo Router 57.0.24 resolves the launch URL asynchronously and can update its own navigator before it mounts on slow devices (dev warning from inside the router). The LogBox overlay covered the screen and broke e2e taps; the message still reaches Metro. Remove the ignore when upstream fixes it | Holding the native splash (needs `expo-splash-screen` + rebuild, and didn't address the router's own race); ignoring all LogBox output                                                                                                                                                                                                          |
| D46 | **`care_tasks.days_of_week` defaults to `{}` and the recurrence CHECK requires `IS NOT NULL`** (fix-forward migration)                                                                                                                                                                                                                                        | Prisma creates scalar lists as nullable; `cardinality(NULL)` is NULL and a CHECK treats NULL as passing, so a WEEKLY rule with NULL days got past the DB guard (found by the care-tasks e2e test)                                                                                                      | Column `NOT NULL` (Prisma's schema diff doesn't model it for lists and would revert it); editing the applied migration                                                                                                                                                                                                                          |
| D47 | **Task time is a 24-hour `HH:MM` text field** (design-system `TimeField`, minutes since midnight, validated by the shared schema) instead of a native time picker                                                                                                                                                                                             | No new native dependency (each one means a rebuild on every machine; iOS builds are blocked locally); the shared schema already validates the value; easy to swap later                                                                                                                                | `@react-native-community/datetimepicker` (native module, rebuild, platform-specific UI)                                                                                                                                                                                                                                                         |
| D48 | **Schedule = rules from `GET /care-tasks`, expanded on the device** (`expandOccurrences`); view mode and pet filter are Jotai atoms, tasks are TanStack Query                                                                                                                                                                                                 | Wall-clock rules expand correctly in the viewer's zone across DST (D11); one request serves Today and This week; UI state stays out of the server cache                                                                                                                                                | Server-side occurrence expansion per range (timezone must be sent and trusted; two cache entries for the same rules)                                                                                                                                                                                                                            |
| D49 | **Accepting an invite is a conditional claim** (`updateMany` where PENDING, unexpired, invitee = me; count must be 1) **+ watcher row in one transaction**; a lost race re-reads and returns success if already accepted. Owners can also **cancel a pending invite** (status REVOKED, link answers 410 `INVITE_REVOKED`)                                     | Same reasoning as D40: two taps / two devices can't both claim, and accepting twice is not an error. The design's Watchers block has Cancel on pending rows and an accept state "cancelled"                                                                                                            | Read-then-write (both concurrent accepts pass the check); deleting the invitation on cancel (the link would say "not found" instead of "cancelled")                                                                                                                                                                                             |
| D50 | **Wrong-account screen doesn't show the invitee's email**; invite tokens are only readable by the invitee's account (403 otherwise)                                                                                                                                                                                                                           | Whoever holds a forwarded link learns nothing about the invitee; "Switch account" re-queues the invite so it reopens after login                                                                                                                                                                       | Showing "this invite is for sam@…" as in the design (leaks the address to any signed-in holder of the link)                                                                                                                                                                                                                                     |
| D51 | **Offline = one `useIsOnline()` (TanStack `onlineManager`, fed by NetInfo) + `Button requiresNetwork="save"`**: offline, write buttons disable themselves with "Connect to the internet to save."; cached queries keep rendering; `useLogout` uses `networkMode: 'always'`                                                                                    | One switch drives paused queries, disabled writes and the banner; a write can't be forgotten screen by screen. Logout is local and must not wait for the network (TanStack pauses mutations offline by default)                                                                                        | An `isOffline` prop threaded through every form; queueing writes for later (conflict handling is out of MVP scope)                                                                                                                                                                                                                              |
| D52 | **Demo seed goes through the running API** (`pnpm db:seed`, `apps/api/scripts/seed.ts`, Node's built-in TypeScript stripping), opt-in and re-runnable                                                                                                                                                                                                         | Real hashing, access rules and invite flow (Sam accepts via the emailed token); no new dependency; never touches a DB directly                                                                                                                                                                         | `prisma/seed.ts` writing rows (needs a TS runner, duplicates business rules, can create states the API never would)                                                                                                                                                                                                                             |
| D53 | **Access matrix as one table** (`test/access-matrix.e2e-spec.ts`): every pet-scoped route × owner / watcher / stranger / anonymous, one generated test per cell, plus a guard that compares the table with the routes Express actually mounted                                                                                                                | The strongest proof of "access rules enforced server-side"; a new pet route without a row fails CI instead of silently skipping the rules                                                                                                                                                              | Per-feature access tests only (they cover most routes, but nothing notices a missing one)                                                                                                                                                                                                                                                       |
| D54 | **CI runs the repo's own `docker-compose.yml`** (`docker compose up --wait` + the s3-init one-shot) for API e2e; Maestro stays local                                                                                                                                                                                                                          | Identical services on laptops and CI; GitHub `services:` can't pass SeaweedFS its command or run the bucket init. Same shape as the SDK 58 template, so the plugin is deleted on upgrade                                                                        | Upgrading to Expo SDK 58 (`next`, React Native 0.88 RC) right before submission; building with an older Xcode 26.x side by side                                                                                                                                                                                                                 |
